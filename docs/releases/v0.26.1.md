**Linux: a daemon with two-way sync, files and owners as with rsync -a; sync made safe against server crashes.**

0.26.1 brings Unix metadata and symbolic links, a Linux daemon that reads and writes every file as the signed-in
user (with two-way sync between a Linux PC and the server), and three sync fixes found by hard-resetting the
receiver in the middle of a round.

### What's new
- **Unix metadata, as with `rsync -a`**: the full mode (incl. setuid, setgid, sticky), nanosecond times of files,
  folders and links, and **symbolic links as links** (never followed, never written through). Owners and groups
  arrive when the receiving side runs as root (`SCOPY_REMOTE="sudo -n scopy"`), matched by name as rsync does;
  `--numeric-ids` keeps them by number. Compared with `rsync -a` on a tree with every case: identical to the source,
  no speed cost (BENCHMARKS.md).
- **Linux daemon**: `sudo scopy service install --share name=/path` installs a systemd service. Users sign in through
  SSH (`ssh host scopy token`; the kernel tells the daemon who is asking) and copy with rsync's daemon syntax,
  `scopy send dir user@host::share/path`; every file is read and written as that user, so the file system's own
  permissions decide. Two users at once: each one's files are owned by them, neither reaches the other's folders.
- **Two-way sync through the daemon**: `/etc/scopy/scopy.toml` on the server, `scopy sync enable --server
  user@host::` and `scopy sync run` on the PC. Changes on the server arrive in about a second (change feed); tokens
  are renewed before they expire; the agent signs in again by itself after a daemon restart.
- **Sync is crash-safe on Windows and Linux** (hard resets of the receiver during uploads, downloads, deletes and
  recycle-bin moves, every file compared by SHA-256): files a reset left zero-filled with the right size and time
  are no longer taken as synced (the server tells the PC, which sends them again; protocol 22), confirmed deletes
  are on disk before the PC hears so, and a round no longer hangs on a dead connection (BENCHMARKS.md).
- **No conflict copies of files still being written on the server**: a big copy onto the share while an agent synced
  could turn half-written files into conflict copies (18 of 20 in a test); the round now records the version it
  actually fetched.

### Download
`StreamCopy-0.26.1-windows-x64.zip` contains `scopy.exe` (client, receiver and Windows services in one),
`scopyw.exe` (tray app), `QUICKSTART.txt`, `README.md` and `LICENSE.md`. Start with **QUICKSTART.txt**.
SHA-256 of every file: `SHA256SUMS.txt`. Built by GitHub Actions from the tagged commit.
`StreamCopy-0.26.1-linux-x64.tar.gz` contains a static x86_64 Linux `scopy` (runs on any distribution, no
dependencies) with README and LICENSE.
